网络渗透测试作业：Easy File Sharing Web Server 远程溢出复现

发表于2026-11-08|更新于2026-11-09|作业
|浏览量:

1.作业与漏洞

课件 ch5 的实例要求走一条完整的”漏洞扫描 → 模块匹配 → 实施利用”链路：靶机装存在远程溢出漏洞的 Easy File Sharing Web Server，Kali 上用 nmap -sV 识别服务、用系统自带的 exploit-db 离线库 searchsploit 匹配渗透模块，最后跑公开 exploit 打垮服务。

命中的漏洞是 EDB-ID 39009：*Easy File Sharing Web Server 7.2 - HEAD Request Buffer Overflow (SEH)*。原理很经典——客户端发一条超长的 HEAD 请求（构造 4500 字节），溢出覆盖结构化异常处理链（SEH），把返回地址改成 pop pop ret 再滑进 shellcode。在本机靶场上的实际效果是服务进程被摧毁（拒绝服务）。

整个过程远程、免认证：不需要任何账号密码，一条畸形请求就能杀死服务。 这正是课件那句”无法阻挡本身漏洞”的含义——防火墙和杀软看着一个完全合法的 HTTP 方法名把进程打崩。

角色 主机 地址 说明
攻击机 Kali GNU/Linux Rolling（aarch64） 172.16.134.131 VMware Fusion 虚拟机， exploit-db 库与 nmap 齐全
靶机 Windows 11 ARM64 172.16.134.133 运行 Easy File Sharing Web Server，监听 8000
宿主机 macOS（Apple Silicon） 172.16.134.1 只负责截屏留证，不参与攻击
🔥授权声明

全部操作只发生在自己电脑上的虚拟网段内，靶机是自已装的漏洞软件。该 exploit 对任何未授权目标执行都属于违法行为。

6.崩溃验证

攻击打完后的状态变化分两个阶段，这个时间线是本次复现里最有信息量的部分：

时间 探测 结果 解释
攻击后数秒 nc -z 172.16.134.133 8000 仍能建立 TCP 连接 监听 socket 还在
同时 curl -m5 -sI http://172.16.134.133:8000/ 超时无响应（http=000） 处理请求的工作线程已被 SEH 溢出摧毁
约 1 分钟后 nmap -p8000 -sV 172.16.134.133 8000/tcp closed 进程彻底死亡，监听套接字被操作系统回收

靶机侧的现场：EFSWS 的 GUI 壳还开着，但底部状态栏已经变成 [Web Server is offline]，工具栏 Start 按钮恢复为可点状态——服务线程没了，只剩一个等待重启的窗口：

这是因为我使用的windows虚拟机是win11版本，而这个漏洞的测试环境是win7，发送payload之后漏洞确实触发成功了，但是win11会触发拒绝服务导致程序崩溃，从而使漏洞无法利用。下一篇文章 使用MSF对软件发起攻击 同样是这个结果。如果想要完全复现，必须使用win7的主机才行。

7.结论与修复

结论：

  1. nmap -sV 的服务指纹可以直接定位”带已知漏洞的软件 + 版本”，是漏洞扫描的起点；
  2. exploit-db / searchsploit 把指纹翻译成可用的渗透模块，匹配时注意 banner 版本与产品版本的错位；
  3. 39009 的 SEH 溢出远程、免认证触发，单条畸形 HEAD 请求即摧毁服务，防护设备无法在漏洞层面拦截；
  4. 崩溃呈现”先 hang 后 closed”的两阶段特征，验证要以应用层响应与最终端口状态为判据。

修复按优先级：

  1. 该软件早已停止维护、无官方补丁，最优先是下线或替换；必须保留时放进隔离网段并限制来源 IP；
  2. 启用系统级缓解：DEP/NX、ASLR、SafeSEH 会让这类 SEH 覆盖从”必崩”变成”大概率崩在攻击者自己手里”；
  3. 服务以低权限账号运行，崩溃或被利用时损失受限；
  4. 检测侧：监控服务的异常消失（本例的 hang → closed 时间线就是特征），HTTP 日志里超长的 HEAD 行应当告警；定期用 nmap NSE / OpenVAS 做漏扫，把”banner 自报版本”纳入资产台账。
