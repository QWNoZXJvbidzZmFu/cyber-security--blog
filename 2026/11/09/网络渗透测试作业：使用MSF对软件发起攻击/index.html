网络渗透测试作业：使用 MSF 对软件发起攻击

发表于2026-11-09|更新于2026-11-09|作业
|浏览量:

0.课本 7.4 的思路

课本 7.4 的前提是：Windows 7 已经打全补丁，操作系统本身找不到洞，于是把目标换成系统上装的软件——Easy File Sharing Web Server 7.2。它有一个 2015 年披露的 HTTP SEH 溢出漏洞，Metasploit 已经收录，直接用它打。

我的靶机是 Windows 11 ARM64，而这个模块需要 Windows 7。所以这次只完成了漏洞发现（软件、版本、模块都能对上），没能拿到会话。上一篇 39009 的复现也是同样的结果。

角色 主机 地址 说明
攻击机 Kali GNU/Linux Rolling（aarch64） 172.16.134.131 运行 msfconsole
靶机 Windows 11 ARM64 172.16.134.133 Easy File Sharing Web Server，监听 8000
🔥授权声明

所有操作只发生在自己电脑上的虚拟网段内。对未授权目标使用 Metasploit 攻击属于违法行为。

2.查找模块

启动 Metasploit 后先搜关键词：

搜出来三个模块，最后一个才是课本要用的 HTTP SEH 溢出（2015 年底发布）。我们的目标是 7.2 的 Web 服务，所以用 easyfilesharing_seh。

3.启动模块并查看参数

show options 只列出模块自己的参数：

参数 默认值 必填 含义
RHOSTS 空 yes 目标地址
RPORT 80 yes 目标端口

课本这里的 RHOST 写法是老版本的；新版本统一叫 RHOSTS。这个模块加载时会自动带上默认载荷 windows/meterpreter/reverse_tcp，所以 show options 里已经能看到 LHOST/LPORT；但默认的 LHOST 不是 Kali 的地址，后面必须手动改。

有两个小坑：

  • 课本图 7-16 前面写的是 set rport80，少了一个空格，Metasploit 会把它当成未知命令；正确写法是 set rport 80。
  • 课本的靶机监听 80，我的 EFSWS 沿用上一篇的 8000，所以 rport 必须显式改掉，否则打的端口根本没人听。

4.发起攻击与实际结果

反连 handler 能正常启动，exploit 也显示发送成功，但后面一直没有出现课本里的 Sending stage 和 Meterpreter session 1 opened。再去看靶机，EFSWS 的状态栏已经由 [Web Server is online] 变成 [Web Server is offline]，8000 端口随后变成 closed。

环节 课本（Win7） 本机（Win11）
模块加载、参数设置 正常 正常
Exploit Sent 有 有
发送 stage 957487 字节，回连 4444 没有出现
会话 Meterpreter session 1 opened 无，服务崩溃

服务崩溃说明漏洞确实被触发了，但这只是拒绝服务，不是拿到控制权。

5.为什么 Win11 上利用不了

  • 这个模块是 2015 年的，针对 Win7 + EFSWS 7.2。SEH 覆盖要借用程序模块里一个固定的 pop pop ret 地址，并依赖当时的栈布局。
  • Win11 默认开启了 ASLR、DEP 等缓解措施，固定地址不再可靠，覆盖之后跳不进 shellcode，进程直接异常终止。
  • 我的靶机还是 ARM64，32 位的 EFSWS 跑在模拟层里，和课本的 x86 Win7 差异更大。

所以结果是“漏洞触发 → 进程崩溃”，而不是“漏洞触发 → 反弹会话”。想完整复现课本图 7-16 的 session，必须换一台 Win7（最好是 32 位） 虚拟机。

6.结论

  1. 漏洞发现不等于漏洞利用。 search 能匹配到模块、banner 能对上版本，只说明“理论上可打”，真正拿到会话还要看目标环境。
  2. 老 exploit 对操作系统版本很敏感。做靶场要按模块的年代选系统，否则只能复现崩溃，复现不了利用。
  3. 修复思路和上一篇一致：停更的软件优先下线或升级，必须保留就放进隔离网段、限制来源 IP，并开启 DEP/ASLR、用低权限账号运行。
